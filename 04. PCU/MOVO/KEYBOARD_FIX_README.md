# 키보드 조종 점검 및 수정

## 확인한 문제

Console 연결 및 D 선택은 정상이어도 D 선택 자체가 가속을 시작하지는 않습니다.
↑를 누르는 동안 가속하고, 떼면 감속하는 기존 방식입니다.
기존 출발 가속량은 Console 정수 km/h 전송에서 0으로 반올림될 수 있어 짧게 누르면 거의 움직이지 않았습니다.

수정 전 직접 주입한 ↑ 키의 실제 기록:
- AAOS Speed = 0.2777778 m/s; 1.0 km/h 수신
- 가상 차량 y=4.0 → 4.029722223639489 이동
즉 앱 → Console → AAOS → 가상 차량 경로는 연결돼 있었지만 짧은 키 입력의 이동량이 매우 작았습니다.
PC에서 누른 키가 앱까지 전달되는지는 별도 확인 대상입니다.

## 수정

- AlleyKeyboardDriver: 가속 키가 눌린 정지 상태의 첫 tick에 1km/h 저속 출발값을 사용합니다.
  브레이크 우선, 최대 6km/h, 키를 떼면 감속, Space 즉시 정지를 유지합니다.
- 방향키와 WASD를 함께 지원합니다.
- 키보드 모드에 실제 KEY_DOWN/KEY_UP 수신 상태를 표시합니다.
- CarTalkKeyboard Logcat에 키 수신과 정수 차속/조향 Console 요청을 기록합니다.
- 기어 버튼 클릭 후 앱의 키보드 입력 포커스를 다시 요청합니다.
- 기존 실제 AAOS/Pleos readback 기반 이동, 기능 2, 50:50 화면, 조명 복원, 매크로는 유지합니다.

## 사용 순서

1. Pleos Virtual Console을 P·0km/h로 설정합니다.
2. Android Studio에서 Running Devices의 Pleos 앱 화면을 표시합니다.
3. 앱의 'Console 키보드 연결'을 누르고 연결 완료를 기다립니다.
4. 앱의 D 버튼을 누릅니다. D는 기어 선택이며 가속 명령은 아닙니다.
5. 앱 화면을 클릭한 상태에서 W 또는 ↑를 길게 누릅니다.
6. 앱에 KEYCODE_W/KEYCODE_DPAD_UP '키 수신됨'이 표시되는지 확인합니다.

- W / ↑: 가속
- S / ↓: 브레이크
- A / ←: 왼쪽 조향
- D / →: 오른쪽 조향 (화면의 D 기어 버튼과 PC의 D 키는 역할이 다릅니다)
- Space: 정지
- 앱을 다른 창으로 전환하면 기존 방식대로 운전을 중단하고 Console 정지/P 복원을 시도합니다.

Chrome Virtual Console이나 IDE 채팅/코드 창에 키보드 포커스가 있으면 Android 앱이 해당 키를 받지 못합니다.
에뮬레이터 앱 화면에서 조작하세요. 키 입력 표시가 계속 '대기'라면 PC 키 전달 경로를 확인해야 합니다.
