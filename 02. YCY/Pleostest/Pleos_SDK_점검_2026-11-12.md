# Pleos SDK 점검 결과 (2026-11-12)

> 아래 본문은 정적 분석 당시 기록이다. 후속 실제 시험은 [SDK 실제제어 검증](SDK_실제제어_검증_2026-11-12.md)을 우선한다.
> 정정: 앰비언트 set 메서드의 인터페이스/KDoc와 달리 실제 LightImpl은 CONTROL_CAR_LIGHTS를 요구하며 런타임에서도 확인했다.
> 미러 열선과 앰비언트 AUTOMATIC 스위치 변경·복원은 성공했고, 창문·도어·밝기·색상은 요청 후 재조회 반영 미확인이다.

## 점검 범위와 근거

기존 브레이크·속도 구현은 유지하고, 후속 Alley Pass 기능의 API·권한을 분석했다.
이번에는 앱 코드, Manifest, Gradle 설정을 수정하지 않았다. 이 보고서와 진행상황 문서만 변경했다.

근거는 Gradle에 다운로드된 공급자 소스 아카이브의 KDoc 및 실제 선언과 에뮬레이터의 설치 패키지 정보이다.
온라인 최신 버전 전체에 대한 조사나 실차 검증 결과가 아니다.

- Vehicle-2.3.2-sources.jar 내부 ai/pleos/playground/vehicle/api/*.kt
- 같은 아카이브의 constant/PleosPermission.kt 및 Vehicle.kt
- FusedLocation-1.1.3-sources.jar의 FusedLocation.kt
- adb shell dumpsys package ai.pleos.playground.service.vehicle
- 기존 앱의 성공한 Gradle 빌드·Sync·배포 및 Logcat 수신 기록

SDK의 타입과 메서드 존재, 장치의 권한 정의, 앱의 권한 승인, 장치 Capability, 실제 읽기·쓰기 성공은 서로 별개의 확인 단계이다.

## 1. SDK 및 Gradle 상태

- Vehicle 2.3.2와 FusedLocation 1.1.3은 의존성으로 선언되어 있고 로컬 소스가 해석되며 기존 앱 빌드·실행에 성공했다.
- Vehicle Service 연결은 브레이크 Capability READ 및 실제 값 수신으로 확인했다.
- FusedLocation은 기존 실행에서 위치 콜백 수신을 확인했다. isSupported()만으로 연결 성공을 판정하지 않았다.
- settings.gradle.kts에 https://nexus-playground.pleos.ai/repository/maven-releases/ 등록.
- AGP 9.5.0, compileSdk/targetSdk 37, minSdk 28. 에뮬레이터 실행 API 34와 앱 컴파일 API는 별개다.
- app/build.gradle.kts의 useLibrary("android.car")와 Manifest의 선택적 uses-library 설정 존재.
- 이번 범위에서 추가 Pleos SDK 설치 필요성은 확인되지 않았다. 거리 데이터를 얻기 위해 SDK를 무작정 추가하지 않는다.

Vehicle 진입점에서 제공하는 도메인:
EvBattery, Fuel, HVAC, Door, Seat, Window, Display, Odometer, Light, Safety, CarInfo,
DrivingMode, Gear, SteeringWheel, Toll, TurnSignal, Wiper, Tire, SideMirror, Brake.
도메인의 존재는 그 안의 모든 속성이 현재 차량에서 지원된다는 뜻이 아니다.

## 2. 권한 점검

아래 Pleos 권한 이름은 pleos.car.permission. 접두사를 사용한다.

| 권한 | 확인 결과 및 추가 시점 |
| --- | --- |
| android.car.permission.CAR_SPEED | 현재 AAOS 속도 수신에 사용하는 권한. 런타임 승인 필요. 앱에서 수신 성공 |
| pleos.car.permission.CAR_SPEED | Vehicle 2.3.2의 PleosPermission 상수에 없음. Vehicle Service 패키지 점검에서도 정의를 확인하지 못함. 추가하지 않음 |
| CAR_DRIVE | 브레이크 및 앞바퀴 조향각 읽기. 현재 앱 선언 |
| CAR_WINDOWS | Window Capability·현재 위치 읽기. SDK 및 에뮬레이터 서비스에서 normal 권한으로 확인. 후속 창문 읽기 테스트에 필요 |
| CONTROL_CAR_WINDOWS | 창문 쓰기. SDK 및 서비스에서 normal 권한으로 확인. 아직 앱에 추가하지 않음 |
| CAR_LIGHTS | 조명 읽기 및 일부 앰비언트 쓰기 API의 현재 SDK 선언. SDK·서비스에서 확인 |
| CONTROL_CAR_LIGHTS | 일부 조명 스위치·주행 모드 자동 색상 설정 등의 쓰기. 해당 API를 사용할 때만 검토 |
| CAR_SAFETY | 실제 존재함. SDK 상수 및 서비스의 normal 권한 정의 확인. 장애물 거리 권한이라는 의미는 아님 |
| CAR_INFO | VIN 읽기에 필요. 불필요한 식별정보 수집을 위해 추가하지 않음 |
| CAR_MIRRORS / CONTROL_CAR_MIRRORS | 사이드미러 열선 읽기·쓰기용. 폴딩을 지원한다는 뜻이 아님 |

현재 앱에는 FUSED_LOCATION, CAR_DRIVE, android.car.permission.CAR_SPEED만 선언되어 있다.
창문·조명 권한이 없는 것은 현재 읽기 테스트 범위에서는 누락 오류가 아니다.
후속 테스트 시 필요한 권한만 추가하고 설치 후 실제 grant 및 Capability를 확인한다.

주의: Light의 setAmbientLightBrightness / setAmbientLightBrightnessColor / setAmbientLightSwitch는
현재 2.3.2 인터페이스와 KDoc에서 CAR_LIGHTS를 요구한다.
모든 조명 쓰기에 CONTROL_CAR_LIGHTS가 필요하다고 일괄 가정하지 않는다.
서비스 내부의 추가 검증 및 장치 지원은 실제 호출 시 별도 확인해야 한다.

## 3. 기능별 실제 API와 테스트 방법

이하 클래스는 별도 표기가 없으면 ai.pleos.playground.vehicle.api 패키지에 있다.
권한 표기는 Pleos 접두사를 생략했다.

| 기능 | 실제 메서드 | Read / Write | 권한 | 자체 앱의 현재 에뮬레이터 검증 |
| --- | --- | --- | --- | --- |
| 속도 | android.car.hardware.property.CarPropertyManager.getCarPropertyConfig, registerCallback; VehiclePropertyIds.PERF_VEHICLE_SPEED | R / 쓰기 없음 | android.car.permission.CAR_SPEED | 15 m/s = 54 km/h 반복 수신. 변화 연동 미검증 |
| Brake | checkBrakePedalStatusCapabilities, getCurrentBrakePedalStatus, registerBrakePedalStatus | R / 쓰기 없음 | CAR_DRIVE | READ 및 PRESSED↔RELEASED 검증 완료 |
| SteeringWheel | checkSteeringWheelAngleCapabilities, getCurrentSteeringWheelAngle, registerSteeringWheelAngle | 각도 R / 각도 쓰기 없음 | CAR_DRIVE | 미호출 |
| Window | checkWindowPositionCapabilities, getCurrentWindowPosition, setWindowPosition, registerWindowPosition | R / W 메서드 존재 | CAR_WINDOWS / CONTROL_CAR_WINDOWS | 미호출. Console 조작 가능과 구분 |
| Light (앰비언트) | checkAmbientLightBrightnessCapabilities, checkAmbientLightBrightnessColorCapabilities, getAmbientLightBrightness, getAmbientLightBrightnessColor, setAmbientLightBrightness, setAmbientLightBrightnessColor | R / W 메서드 존재 | 위 메서드는 CAR_LIGHTS | 미호출 |
| SideMirror | checkHvacSideMirrorHeatCapabilities, getHvacSideMirrorHeatState, setHvacSideMirrorHeat | 열선 R / W. 폴딩 API 없음 | CAR_MIRRORS / CONTROL_CAR_MIRRORS | 미호출 |
| Safety | checkAirbagCapabilities, hasSeatAirbagEnabled, hasSeatAirbagBeenDeployed, hasSeatBeltNotBuckledWarning, getBrakeFluidLevelState 등 | 해당 상태 R. 거리 R/W 없음 | 주로 CAR_SAFETY | 미호출 |
| CarInfo | checkVINInfoCapabilities, getVINInfo | VIN R / 쓰기 없음 | CAR_INFO | 미호출. 모델·차폭·전장 API는 이 인터페이스에 없음 |
| TurnSignal | checkTurnSignalStateCapabilities, getCurrentTurnSignalState, registerTurnSignalState | R / 쓰기 없음 | CAR_LIGHTS | 미호출. 비상등 작동 API로 간주하지 않음 |

### 조향각

SDK KDoc에 따르면 getCurrentSteeringWheelAngle은 앞바퀴 조향각(degrees)이다.
왼쪽은 음수이며 핸들 자체의 회전각이 아니다.
Capability의 AreaBounds<Float>를 기록한 뒤 현재값 조회·구독하고 Console STEERING 조작과 비교한다.
핸들 180도 회전 안내 등에 직접 사용하지 않는다.

### 창문

권장 호출 순서:

1. CAR_WINDOWS 선언 및 grant 확인.
2. Vehicle.getWindow().
3. checkWindowPositionCapabilities의 새 오버로드 사용:
   onComplete: (CapabilityConfig, Map<WindowArea, AreaBounds<Int>>) -> Unit.
4. 지원 영역과 min/max, accessType을 기록한다.
5. 해당 장치의 조수석 영역을 확인한 후 getCurrentWindowPosition(area, onComplete, onFailed).
6. Console에서 창문을 움직이고 registerWindowPosition 이벤트와 비교.
7. 쓰기는 별도 단계에서 CONTROL_CAR_WINDOWS 및 WRITE/READ_WRITE 확인.
8. 안전 정차·기어 등 최신 상태가 확인되고 사용자가 버튼을 누른 경우에만
   setWindowPosition(area, value, onComplete, onFailed) 호출.
9. 완료 콜백 뒤 getCurrentWindowPosition으로 재조회하여 실제 적용값 비교.

위치 Int의 범위를 0~100% 또는 정확한 cm로 임의 해석하지 않는다.
아직 조수석 영역, 실제 범위, 읽기·쓰기 성공 여부 모두 미검증이다.
현재 브레이크 눌림이나 속도 단독 값만으로 안전 정차를 확정하지 않는다.

### 앰비언트 라이트

- Capability로 지원 SeatArea와 밝기 범위를 확인한 후 읽기부터 수행.
- setAmbientLightBrightnessColor의 KDoc: 불투명 32비트 ARGB, alpha=0xFF.
- 따라서 ARGB 표현은 확인됐지만 특정 빨강 색상이 장치에서 적용되는지는 미검증.
- 쓰기 테스트는 사용자가 요청한 상태에서 수행하고 원래 값을 기록·복원하며 재조회로 검증한다.
- Light 및 TurnSignal의 확인한 인터페이스에 비상등 전용 제어 메서드는 없다.

### 사이드미러

SideMirror 인터페이스는 열선 API를 제공한다. 접기·펴기 메서드는 없다.
Alley Pass 폴딩 기능을 지원된다고 표시하지 않는다.
열선 구독의 일부 권한 주석은 CAR_CLIMATE로 되어 있어 읽기·쓰기와 다른 선언이 있으나,
열선은 MVP 우선 기능이 아니므로 이번에는 호출하거나 권한을 추가하지 않았다.

### Safety / ADAS / 거리

확인한 Safety 전체 인터페이스는 에어백, 안전벨트 경고, 오일·워셔액 상태, 경고등 중심이다.
주변 차량 거리, 좌우 여유 공간(cm/m), PDW 근접 단계 API는 찾지 못했다.
Vehicle의 도메인 진입점에도 별도 ADAS/거리 도메인은 확인되지 않았다.

결론의 범위는 현재 공개 Vehicle 2.3.2 인터페이스이다.
플랫폼 내부나 다른 비공개 SDK에도 거리 데이터가 전혀 없다고 단정하지 않는다.
추가 공식 자료가 제공되기 전 MVP는 거리만 SIMULATION으로 분리하는 구성이 적절하다.
실제 속도·브레이크와 가상 거리를 한 화면에서 함께 사용할 때도 각 필드의 출처를 각각 표시해야 한다.

### CarInfo

getVINInfo는 차량 식별번호 조회이며 모델·차체 제원 조회 API가 아니다.
getCapabilityInfo는 PRIVATE_CAR_INFO가 필요한 별도 내부 성격의 API이므로
일반 공개 Capability 확인을 대신할 우회 수단으로 사용하지 않는다.
차폭·전장 등이 필요하면 별도 검증된 모델 정보 또는 사용자가 선택한 시연용 제원임을 명시한다.

## 4. 다음 작업 순서 및 예정 파일

브레이크·속도 테스트를 새로 작성할 필요는 없다.

1. 기존 CarTalkSpeed 로그로 Console 가속·감속 변화 연동 확인.
2. 창문 읽기 전용 테스트: Capability, 지원 영역, 범위, 현재값과 변화 로그 확인.
3. 기어·정차 상태 수신과 데이터 신선도 처리 후 명시적 버튼 기반 창문 쓰기 테스트.
4. 공통 차량 상태 및 거리 시뮬레이션 분리, Alley Pass UI·규칙 엔진.
5. 조명과 음성 모듈 통합.

다음 창문 읽기 단계의 예정 변경 파일:
- 신규 PleosWindowTest.kt: 창문 Capability 및 읽기·구독 진단.
- MainActivity.kt: 진단 시작·정리 연결.
- AndroidManifest.xml: CAR_WINDOWS만 우선 추가.
- Alley_Pass_개발_진행상황.md: 실제 결과 기록.

창문 쓰기 단계가 되기 전에는 CONTROL_CAR_WINDOWS나 실제 제어 호출을 추가하지 않는다.
이번 요청의 '우선 코드 수정 없이 분석' 지시에 따라 위 항목들은 아직 구현하지 않았다.
