## 1. 개요

### 1-1. 해결하려는 문제

초보 운전자는 다음 세 상황에서 판단이 늦거나 과하게 긴장합니다.

| 상황 | 운전자가 모르는 것 |
|---|---|
| 좁은 골목 | 왼쪽·오른쪽에 실제로 몇 cm가 남았는지 |
| 양쪽 주차 구간 | 어느 쪽으로 붙어서 지나가야 하는지 |
| 좁은 길 대향차 | 지나갈 수 있는지, 어디서 멈춰 양보해야 하는지 |

### 1-2. Carity가 하는 일

1. 블랙박스 영상을 YOLO로 라벨링해 차량·보행자 위치를 얻습니다.
2. 라벨을 도로 위 장애물(가상 골목)로 바꾸고 좌우 간격을 계산합니다.
3. 지나갈 경로를 계획하고, **규칙 엔진이 행동을 결정**합니다.
4. **AI(Qwen 또는 Claude)는 결정을 바꾸지 않고**, 운전자에게 들려줄 문장과 근거를 다듬습니다.
5. 결과를 음성으로 안내하고, 튜토리얼에서 노면 화살표와 "먼저 움직이는 차"로 보여 줍니다.

### 1-3. 설계 원칙

| 원칙 | 이유 |
|---|---|
| 안전 결정은 규칙 엔진이 즉시, 결정론적으로 | 대향차는 2~4초 안에 다가옵니다. LLM은 수백 ms~수십 초 지연이 있고 같은 입력에도 답이 달라질 수 있습니다. |
| AI는 설명·코칭 문장만 | "결정은 로직, 설명은 LLM" 구조가 검증과 심사 설명에 유리합니다. AI가 더 위험한 행동을 말하면 무시합니다. |
| 거리 계산은 한 곳(`AlleyWorld`)에서만 | 시뮬레이션·라벨 장면·튜토리얼·검증이 같은 거리 엔진을 써서 값이 어긋나지 않습니다. |
| 차선 대신 장애물 안쪽 모서리와 벽 | 골목에는 차선이 거의 없습니다. |
| 실제 차량 제어 없음 | 조명·매크로·주행은 시연(가상)입니다. 주행 제한을 우회하지 않습니다. |

## 2. 시스템 구성

### 2-1. 구성 요소

```
┌───────────── PC (Windows) ─────────────┐        ┌──────── Pleos 에뮬레이터 / 차량 ────────┐
│ labeling_server (FastAPI :8765)        │◄──────►│ 가디언즈 라벨 뷰어 (viewer)             │
│  ├ YOLO11s(GPU) / YOLOv8n(CPU) 라벨링   │ HTTP   │  영상 탐색 · 라벨 박스 · 라벨링 요청     │
│  ├ /api/files /api/labels /api/media   │        │                                          │
│  └ /api/tts  Windows 한국어 음성(WAV)   │◄──────►│ MOVO (app)                               │
│ Ollama (:11434) qwen2.5:3b             │◄──────►│  ├ 3D 골목 시뮬레이션 (On-sense V1)      │
└────────────────────────────────────────┘        │  ├ [라벨 장애물·AI 판단] 탭             │
                                                  │  └ On-sense 튜토리얼 (별도 런처 아이콘)  │
                                                  └──────────────────────────────────────────┘
에뮬레이터에서 PC 주소 = 10.0.2.2
```

### 2-2. 처리 흐름

```
라벨 JSON(프레임별 박스)
  → [4장] 투영: 박스 → 전방거리 Z, 좌우 X → 장애물·벽 (LabelScene → AlleyWorld)
  → [4장] 거리 검증: 라벨 기대값 vs AlleyWorld 측정값 (±2cm)
  → [5장] 경로 계획: CorridorPlanner → CLEAR / YIELD / BLOCKED
  → [6장] 규칙 엔진: AlleyDecisionEngine → 행동·심각도·음성 문장 (최종 결정)
  → [6장] AI 다듬기: AiJudge(Claude 또는 Qwen) → AiJudge.merge (덜 조심스러운 답 거부)
  → [7장] 음성: Pleos TTS → Android TTS → PC 음성
  → [8장] 화면: 시뮬레이션 탭 / 튜토리얼
```

### 2-3. 소스 위치

| 모듈 | 위치 | 패키지 |
|---|---|---|
| MOVO 앱 | `android/app` | `com.example.pleostest` |
| 가디언즈 라벨 뷰어 | `android/viewer` | `com.guardians.viewer` |
| 라벨링 서버 | `server/labeling_server` | Python(FastAPI, ultralytics) |
| 통합 실행기 | `Carity.bat`, `carity.ps1` | PowerShell |

## 3. 데이터 준비 — YOLO 라벨링

자세한 수치는 `docs/YOLO_분석_작업보고서.md`에 있습니다. 여기서는 Carity가 쓰는 결정만 요약합니다.

### 3-1. 모델 선택

| 용도 | 모델 | 근거 (골목 영상 122프레임 실측) |
|---|---|---|
| 사전 라벨링 (GPU 있을 때) | **YOLO11s** | 근거리 차량 재현율 0.89, 정확도 점수 83.3 (1위) |
| 사전 라벨링 (CPU만) | **YOLOv8n** | n급 중 근거리 차량 재현율 0.78로 1위 |
| 추적 | ByteTrack | 객체 ID 유지 → 1초 전 대비 크기 변화로 대향차 판정 |

서버는 시작할 때 CUDA를 확인해 자동으로 고릅니다(`labeler.py`).

### 3-2. 라벨 JSON 형식 (서버 출력)

```json
{
  "clip": "REC2_20261114_113108",
  "frames": [
    { "t": 18.0,
      "objects": [ { "id": 315, "cls": "car", "conf": 0.89, "box": [0.62, 0.55, 0.88, 0.80] } ] }
  ]
}
```

- `box`는 화면 비율 좌표 `[x1, y1, x2, y2]` (0~1)
- 저장 위치: `DATA_ROOT/_labels/<영상 상대경로>.json`

### 3-3. 앱 내장 검증 장면

`android/app/src/main/assets/label_samples/index.json`에 6개 장면을 넣어, 서버 없이도 기능을 확인할 수 있습니다.

| 장면 | 파일 · 시점 | 기대 결과 | 내용 |
|---|---|---|---|
| 1 | 113108 · 18.0초 | CLEAR | 양쪽 주차 골목, 여유 통과 |
| 2 | 113108 · 29.9초 | CLEAR | 좌측 주차차 옆 통과 |
| 3 | 114202 · 8.6초 | CLEAR | 우측 차량 근접, 왼쪽으로 비켜 통과 |
| 4 | 112432 · 7.7초 | CLEAR | 좁은 골목, 감속 통과 |
| 5 | 113906 · 24.0초 | BLOCKED | 양쪽 주차로 막힌 골목, 정차 |
| 6 | 114118 · 4.4초 | BLOCKED | 대향차 접근, 비켜설 곳 없음 |

## 4. 라벨 → 장애물 변환과 거리 계산

구현: `LabelScenario.kt` (`DashCamera`, `LabelSceneBuilder`), `LabelDistanceCheck.kt`

### 4-1. 카메라 가정 (캘리브레이션 전)

| 값 | 기호 | 설정 |
|---|---|---|
| 지평선 위치 | h | 화면 높이의 0.53 |
| 초점거리/화면폭 | f | 0.384 (수평 화각 약 105°) |
| 카메라 높이 | H | 1.30 m |
| 보닛 끝 | — | 화면 높이의 0.82 (이보다 아래는 보이지 않음) |
| 화면비 | a | 16:9 |

### 4-2. 투영 식

박스 아래 변 y₂와 좌우 x로 노면 위치를 구합니다(평지 핀홀 근사).

```
전방거리  Z = H · f · a / (y₂ − h)          (y₂ ≤ h 이면 지평선 위 → 버림)
좌우위치  X = (x − 0.5) · Z / f             (왼쪽이 음수)
```

- 보닛에 잘린 박스(y₂ ≥ 0.81)는 실제보다 가까우므로 Z = 보닛 끝이 보이는 최소거리(약 3.1 m)로 둡니다.
- 박스의 **안쪽 모서리**(왼쪽 객체는 x₂, 오른쪽 객체는 x₁)가 자차와의 간격을 정합니다.
- 객체 크기는 종류별 기본값을 씁니다: 승용차 1.8×4.4 m, 트럭 2.0×6.0 m, 버스 2.3×9.0 m, 보행자 0.6×0.6 m, 자전거 0.6×1.7 m, 오토바이 0.8×2.0 m.

### 4-3. 걸러내는 박스

| 조건 | 처리 | 이유 |
|---|---|---|
| 신뢰도 < 0.4 | 버림 | 오검출 |
| 보닛에 잘림 + 신뢰도 < 0.5 | 버림 | 보닛 반사 오검출이 많음 |
| 폭 > 화면 80%, 또는 화면 대부분을 덮음 | 버림 | 자차 보닛·벽을 차로 오검출 |
| 전방 32 m 초과 | 버림 | 거리 오차가 큼 |
| 같은 위치 겹친 박스(car/truck 중복) | 신뢰도 높은 것 하나 | 중복 검출 |

### 4-4. 객체 역할

| 역할 | 판정 기준 | 장애물 처리 |
|---|---|---|
| 측면 장애물 | 진행 폭(±1.1 m)에 0.3 m 미만 걸침 | 안쪽 모서리를 기준으로 배치 |
| 경로상 장애물 | 진행 폭에 0.3 m 이상 걸침 | 보이는 범위 전체(대각선 차량은 길이 포함, 최대 차폭+1 m)를 막힌 것으로 |
| **대향차** | 경로상 + 차량 + **1초 전 대비 박스 높이 증가율 ≥ max(1.08, 측면 정지물체 증가율 × 1.1)** | 경로 계획에서 마주치는 지점부터 차로를 차지 |

대향차를 위치만으로 판단하면 경로에 걸친 주차차를 대향차로 오판합니다(보고서 v1의 실패 원인). 그래서 "정지한 측면 물체보다 뚜렷하게 빨리 커지는 경로상 차량"만 대향차로 봅니다.

### 4-5. 장면(세계) 구성

| 항목 | 값 |
|---|---|
| 자차 출발 위치 | y = 4 m, x = 0 (차체 1.8 × 4.2 m) |
| 판단 시점보다 앞에서 출발 | 장면 전체를 6 m 앞으로 밀어 접근 구간 확보 |
| 카메라 위치 | 차량 중심보다 0.6 m 앞 |
| 벽(골목 경계) | 좌우 각각 max(2.4 m, 가장 바깥 객체 + 0.3 m) |
| 도로 끝 | max(30 m, 가장 먼 객체 + 10 m) |

> 벽·연석은 YOLO가 검출하지 않으므로 객체 바깥쪽을 경계로 추정합니다. 실제 벽보다 넓게 잡힐 수 있습니다(10장).

### 4-6. 거리 계산 검증

라벨로 만든 장면의 거리가 올바로 계산되는지 객체마다 확인합니다.

- **기대값**: 투영 좌표로 직접 계산한 "차체 옆면 ↔ 객체 안쪽 모서리" 거리
- **측정값**: 그 객체 하나만 둔 `AlleyWorld`에서 자차를 곧게 통과시키며 `clearance()`로 잰 최소 간격
- 경로상 객체는 자차를 반대쪽으로 0.5 m 비켜 통과시켜 잽니다.
- **허용 오차 2 cm** — 화면에 `거리 검증 n/n 일치`와 객체별 기대/측정값을 표시합니다.

## 5. 경로 계획

구현: `CorridorPlanner.kt`

### 5-1. 방법

1. 출발점부터 도로 끝까지 **0.5 m 간격 단면**을 만듭니다.
2. 단면마다 차량 중심이 갈 수 있는 x 구간을 구합니다. 차체 반폭 0.9 m와 여유 0.25 m를 더해 장애물·벽을 뺍니다.
3. 구간 안에서 목표 x를 고릅니다. 좁으면(폭 < 1 m) 가운데로 가고, 넓으면 현재 위치를 유지하면서 장애물에서 0.3 m 더 떨어집니다.
4. **조향 한계**: 0.5 m 진행에 횡이동 0.15 m(기울기 0.3)까지만 허용합니다. 뒤에서 앞으로 한 번 다듬어 필요한 횡이동을 미리 시작하고, 앞에서 뒤로 한 번 다듬어 출발점과 잇습니다.
5. **차체 회전 보정**: 횡이동 중에는 차체가 틀어져 모서리가 장애물에 가까워집니다. 회전을 반영한 실제 간격이 0.35 m보다 작으면 두 가지를 시도합니다. 하나는 반대쪽으로 밀어내는 것이고, 다른 하나는 횡이동을 더 완만하게(진입은 일찍, 이탈은 늦게) 바꾸는 것입니다. 들어갈 수 있으면서 최소 간격이 가장 큰 경로를 고릅니다.

### 5-2. 결과

| 결과 | 조건 | 경로 |
|---|---|---|
| `CLEAR` | 모든 단면을 통과 | 도로 끝까지 |
| `YIELD` | 대향차가 있고, 옆으로 비켜 설 곳이 있음 | **오른쪽 우선**(우측통행). 대향차 2 m 앞까지 중 가장 앞쪽 정차점. 대향차가 지나갈 폭(차폭 + 양쪽 0.3 m)이 남아야 함 |
| `BLOCKED` | 지나갈 수 없음 | 막힌 지점 1.5 m 앞에서 정차 |

대향차는 처음부터 차로를 막는 것으로 보지 않습니다. **두 차가 만나는 지점**(현재 간격의 절반)에서 차체 길이와 1 m를 뺀 지점부터 막습니다.

### 5-3. 출력

경로 점마다 `x, y, 진행 방향, 좌·우 간격, 최소 간격`을 담고, 경로 전체의 `최소 좌/우 간격`, `가장 좁은 점`, `정차 지점`, `설명 문구`를 함께 돌려줍니다.

## 6. 판단 — 규칙 엔진과 AI(Qwen/Claude)

### 6-1. 역할 분담

| 구분 | 규칙 엔진 (`AlleyDecisionEngine`) | AI (`AiJudge`) |
|---|---|---|
| 하는 일 | 행동 결정, 심각도, 기본 음성 문장 | 음성 문장 다듬기, 판단 근거 문장 |
| 응답 시간 | 즉시 (밀리초) | Qwen 약 12초(PC CPU 측정), Claude 수 초 |
| 결정 권한 | **최종** | 없음 (더 위험한 행동을 말하면 무시) |
| 실패 시 | — | 규칙 문장으로 자동 대체 |

### 6-2. 행동 종류

| 행동 | 한국어 표시 | 위험도 순위 | 의미 |
|---|---|---|---|
| `PROCEED` | 천천히 진행 | 0 | 여유 충분 |
| `KEEP_LEFT` / `KEEP_RIGHT` | 왼쪽/오른쪽으로 조정 | 1 | 한쪽이 가까움 |
| `SLOW` | 감속 | 2 | 좁은 구간, 과속, 앞에서 막힘 |
| `YIELD_RIGHT` / `YIELD_LEFT` | 오른쪽/왼쪽 정차·양보 | 3 | 대향차를 먼저 보냄 |
| `STOP` | 정차 | 4 | 초근접, 접촉, 통과 불가 |
| `REVERSE` | 정차 후 후진 | 4 | 대향차 + 비켜설 곳 없음 |

심각도: 0 안내 · 1 주의 · 2 경고 · 3 긴급

### 6-3. 판단 규칙 (위에서부터 먼저 맞는 규칙 하나를 적용)

| 순서 | 조건 | 행동 | 심각도 | 음성 문장 예 |
|---|---|---|---|---|
| 1 | 차체 접촉 | STOP | 3 | "접촉했습니다. 즉시 정차하고 주변을 확인하세요." |
| 2 | 최근접 ≤ 0.3 m (앞) | STOP | 3 | "앞이 25센티미터로 너무 가깝습니다. 정차하세요." |
| 2 | 최근접 ≤ 0.3 m (옆) | STOP | 3 | "왼쪽에 너무 가깝게 붙었습니다. 정차 후 핸들을 오른쪽으로 돌려 천천히 빠져나오세요." |
| 3 | 경로 YIELD + 대향차 40 m 이내 | YIELD_RIGHT/LEFT | 2 | "앞에서 차가 옵니다. 오른쪽 빈 곳에 붙어 정차하고 먼저 보내세요." |
| 4 | 경로 BLOCKED + 정차점까지 < 8 m | REVERSE(대향차 있음) / STOP | 2 | "비켜설 공간이 없습니다. 정차 후 천천히 후진해 넓은 곳에서 양보하세요." |
| 5 | 경로 BLOCKED + 정차점까지 < 25 m | SLOW | 1 | "앞쪽 길이 좁아 지나가기 어렵습니다. 속도를 줄이고 정차를 준비하세요." |
| 6 | 속도 > 10 km/h + 최근접 < 1.2 m | SLOW | 2 | "좁은 길입니다. 시속 10킬로미터 이하로 천천히 가세요." |
| 7 | 최근접 < 0.6 m + 좌우 차이 > 0.3 m | KEEP_반대쪽 | 1 | "왼쪽에 가깝습니다. 40센티미터입니다. 핸들을 오른쪽으로 살짝 돌리세요." |
| 8 | 좌우 모두 < 0.6 m | SLOW | 1 | "양쪽이 모두 좁습니다. 가운데를 유지하며 천천히 지나가세요." |
| 9 | 앞 12 m 안 경로 최소 간격 < 0.5 m | SLOW | 1 | "앞에 좁은 구간이 있습니다. 왼쪽 간격이 35센티미터까지 줄어드니 천천히 가세요." |
| 10 | 위 조건 없음 | PROCEED | 0 | "좌우 여유가 충분합니다. 천천히 진행하세요." |

- 기준값 0.3 m / 0.8 m는 기존 On-sense 경고 등급(빨강/주황)과 같습니다. 0.6 m는 "핸들 조정 권고" 기준입니다.
- 음성 거리는 읽기 쉽게 바꿉니다. 1 m 미만은 5 cm 단위 "35센티미터", 1 m 이상은 "1.2미터"입니다.
- 같은 상황이 이어질 때 반복해서 말하지 않도록, 판단마다 **상황 키**(행동 + 방향)를 둡니다.

> **팀 검토 필요**: 설계안(`좁은길_회피판단_시퀀스.md` S6)은 "후진 유도는 초보자에게 위험하므로 제외"입니다. 현재 구현은 대향차가 있고 비켜설 곳이 전혀 없을 때만 `REVERSE`를 안내합니다. 제외하려면 규칙 4의 행동을 `STOP`으로 바꾸면 됩니다.

### 6-4. AI 판단 (Qwen / Claude)

#### 제공자 선택

| 조건 | 사용 모델 | 호출 방식 |
|---|---|---|
| `.env`에 `ANTHROPIC_API_KEY` 있음 | Claude (`claude-haiku-5-5`) | Messages API |
| 키 없음 (기본) | Qwen (`qwen2.5:3b`, PC의 Ollama) | OpenAI 호환 `/v1/chat/completions`, `temperature 0.2` |

연결 제한시간은 4초, 응답 제한시간은 15초입니다. 키는 빌드할 때 APK에 들어가므로 외부 배포 빌드에는 넣지 않습니다.

#### 입력 (원본 영상이 아니라 정리된 측정값과 규칙 결과)

```json
{
  "measurements": {
    "left_m": "0.42", "right_m": "1.10", "front_m": "6.30",
    "nearest_obstacle": "왼쪽 주차 차량", "speed_kmh": "8.0",
    "road_width_m": "5.20", "oncoming_ahead_m": "none",
    "plan": "CLEAR:끝까지 통과 가능", "plan_min_left_m": "0.35", "plan_min_right_m": "0.41",
    "scene": "왼쪽 1개 · 오른쪽 0개 · 대향 0개 · 경로상 1개 · 도로폭 5.2m"
  },
  "rule": {
    "action": "KEEP_RIGHT", "severity": 1,
    "headline": "왼쪽 40센티미터 · 오른쪽으로",
    "speech": "왼쪽에 가깝습니다. 40센티미터입니다. 핸들을 오른쪽으로 살짝 돌리세요.",
    "reasons": ["왼쪽 0.42m, 오른쪽 1.10m"]
  }
}
```

#### 지시문 (음성 안내용 프롬프트) 요약

1. 안전 판단은 `rule.action`이 최종입니다. 규칙보다 덜 조심스러운 행동(진행·가속)을 권하지 않습니다.
2. `speech`는 TTS로 바로 읽을 한국어 존댓말 한 문장, 45자 이내입니다. 순서는 **어느 쪽 → 얼마나 가까운지 → 무엇을 할지**입니다.
3. 영어·기호·괄호·이모지·소수점 숫자를 쓰지 않고, 거리는 "30센티미터", "1.2미터"처럼 읽는 말로 씁니다.
4. `action`은 정해진 8개 중 하나만 씁니다.
5. 출력은 JSON 하나입니다: `{"action": "...", "speech": "...", "reason": "..."}`

#### 응답 처리

1. `<think>` 블록과 코드펜스를 지우고, 첫 `{`부터 마지막 `}`까지를 JSON으로 읽습니다.
2. 음성 문장에서 괄호·기호를 지우고 80자로 자릅니다.
3. **결합 규칙** (`AiJudge.merge`):

| 경우 | 최종 행동 | 읽을 문장 | 출처 표시 |
|---|---|---|---|
| AI 실패·응답 없음 | 규칙 | 규칙 문장 | 규칙 엔진 |
| 규칙 심각도 3(긴급) | 규칙 | 규칙 문장 | 규칙 엔진(긴급) |
| AI 행동이 규칙보다 덜 위험 | 규칙 | 규칙 문장 | 규칙 엔진(AI 완화 거부) |
| 그 밖 | 규칙 | **AI 문장** | Claude 또는 Qwen |

#### 호출 시점

- 상황 키가 바뀌고 0.4초 동안 유지되면 1회 호출합니다. 깜빡이는 상황은 호출하지 않습니다.
- 더 새 요청이 들어오면 이전 결과는 버립니다(`AiCoordinator`).
- 장면을 처음 적용했을 때(정차 상태)도 1회 호출해 장면 판단을 읽어 줍니다.

### 6-5. 장면 안내 문장 (튜토리얼·장면 적용 시)

`SceneAnalysis`가 장면과 경로에서 만들어 냅니다. AI 없이도 동작합니다.

| 문장 | 생성 규칙 | 예 |
|---|---|---|
| 상황 설명 | 도로폭 + 좌/우/가운데 장애물 수 + 대향차 여부 | "길 폭은 5.2미터입니다. 왼쪽에 한 개, 길 가운데에 한 개 장애물이 있습니다." |
| 경로 안내 | 경로가 출발점에서 0.3 m 넘게 움직인 방향 + 가장 좁은 곳 + 결과 | "노면 화살표를 따라 왼쪽으로 붙어서 천천히 가세요. 가장 좁은 곳은 오른쪽 35센티미터입니다. 끝까지 지나갈 수 있습니다." |
| 마무리 | 결과별 고정 문장 + 최소 간격 | "잘 지나갔습니다. 가장 가까웠던 간격은 왼쪽 35센티미터, 오른쪽 40센티미터입니다." |

## 8. 화면 기능 — 시뮬레이션 탭과 튜토리얼

### 8-1. 시뮬레이션 `[라벨 장애물·AI 판단]` 탭

기존 On-sense 화면(왼쪽 3D 골목 / 오른쪽 실내 조명)의 오른쪽 패널에 탭을 추가했습니다. `[실내 조명]` 탭은 기존 기능 그대로입니다.

| 영역 | 내용 |
|---|---|
| 장면 선택 | 기본 골목 · 합성 대향차 연습 · 앱 내장 라벨 6개 · **PC 라벨 불러오기**(서버 폴더 탐색 → 판단이 필요한 순간 자동 추천) |
| 장면 | 객체별 종류·위치(왼쪽/오른쪽/가운데)·전방거리·안쪽 모서리 |
| 거리 계산 검증 | `n/n 일치`와 객체별 기대/측정값 |
| 경로 계획 | 결과, 최소 좌/우 간격, 정차 지점, 실시간 좌·우·앞 간격 |
| 규칙 엔진 판단 | 행동·근거·음성 문장 (심각도별 색) |
| AI 판단 | 제공자, 응답 시간, AI 권고, 최종 음성 문장, 재생 출처 |
| 버튼 | 판단 음성 듣기 · AI 다시 판단 · 튜토리얼로 보기 · 기본 골목으로 |

- 장면을 고르면 3D 골목의 벽·장애물이 라벨 기준으로 바뀝니다.
- **3D 자동 시연**은 라벨 장면에서 경로 계획을 따라 달립니다. 기본 2.5 m/s이고, 앞 4 m 안에 0.5 m보다 좁은 곳이 있으면 1.2 m/s로 줄이며, 정차점에서 멈춥니다.
- 주행 중에는 1초마다 현재 위치에서 경로를 다시 계획해 판단에 씁니다.

### 8-2. On-sense 튜토리얼 (별도 런처 앱)

같은 APK 안의 별도 아이콘(`TutorialActivity`)입니다. 위에서 본 디지털 트윈 화면(`TutorialView`)과 오른쪽 안내 패널로 구성합니다.

#### 단계

| 단계 | 화면 | 음성 | 다음 단계로 넘어가는 조건 |
|---|---|---|---|
| 1 상황 파악 | 장애물 강조(깜빡임), 카메라가 앞쪽 장애물까지 훑고 돌아옴 | 상황 설명 문장 | 6.5초 |
| 2 AI 판단 | 규칙 판단 카드 → AI 결과 카드 | 최종 음성 문장 (AI 또는 규칙) | AI 결과 후 4.5초, 최대 14초 |
| 3 노면 방향 표시 | 자차 폭 띠 + 흐르는 화살표(쉐브론)가 3초 동안 경로를 따라 펼쳐짐, 정차선 표시 | 경로 안내 문장 | 7초 |
| 4 미리 보기 | 투명한 "고스트 차"가 경로를 4 m/s로 먼저 주행 | "투명한 차가 먼저 지나가는 길을 보여 드릴게요." | 고스트가 끝까지 + 마무리 동작 |
| 5 따라 주행 | 실제 자차가 2 m/s로 주행(좁은 곳 절반 속도), 좌우 간격선과 수치, 판단 카드 | 상황이 바뀔 때마다 규칙 문장 | 끝까지 + 마무리 동작 |
| 6 정리 | 결과와 최소 간격 카드 | 마무리 문장 | (처음부터 버튼) |

#### 결과별 마무리 동작 (4·5단계)

| 결과 | 동작 |
|---|---|
| CLEAR | 끝 지점 도착 후 0.6초 뒤 다음 단계 |
| YIELD | 정차("여기서 정차하고 마주 오는 차를 먼저 보내세요.") → 대향차가 자차 옆 빈 차로로 옮겨 5 m/s로 지나감 → 완전히 지나간 뒤 1초 |
| BLOCKED (대향차 없음) | 정차선 앞 정차("앞이 차 폭보다 좁습니다.") → 2.5초 |
| BLOCKED (대향차 있음) | 후진 화살표 + 5 m를 1.2 m/s로 후진 시연 |

#### 화면 요소

| 요소 | 표현 |
|---|---|
| 장애물 | 승용차 파랑, 트럭·버스 보라, 경로상 객체 주황, 보행자 원형, **대향차 빨강 + 아래쪽 화살표** |
| 경로 | 청록 띠 + 흐르는 쉐브론 |
| 정차선 | 양보 정차는 주황, 정차는 빨강 |
| 간격 표시 | 0.3 m 이하 빨강 · 0.8 m 이하 주황 · 그 밖 청록 (기존 경고 등급과 같음) |

조작 버튼: 장면 선택, 처음부터, 일시정지/계속, 다음 단계, 음성 켬/끔. 시뮬레이션 탭의 "튜토리얼로 보기"로 같은 장면을 바로 열 수 있습니다.

## 12. 부록 — 용어, 상수, 파일 목록

### 12-1. 용어

| 용어 | 뜻 |
|---|---|
| 간격(clearance) | 자차 차체(회전 반영)와 가장 가까운 장애물·벽 사이 거리 |
| 안쪽 모서리 | 장애물에서 자차 쪽 가장자리 |
| 경로상 객체 | 자차 진행 폭(±1.1 m)에 0.3 m 이상 걸친 객체 |
| 대향차 | 경로상에서 정지물체보다 뚜렷하게 빨리 커지는(다가오는) 차량 |
| 상황 키 | 같은 안내를 반복하지 않기 위한 판단 식별자 (행동 + 방향) |
| 고스트 차 | 튜토리얼에서 경로를 먼저 보여 주는 반투명 차 |
