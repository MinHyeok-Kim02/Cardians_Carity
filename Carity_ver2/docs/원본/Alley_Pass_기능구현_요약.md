# Alley Pass 기능 구현 요약



## 1. 문서 목적

이 문서는 **Alley Pass(좁은 골목길 교행 보조)** 프로젝트에서 실제로 구현한 기능을 기획서용으로 간단히 정리한 자료이다.  
음성 인식 및 음성 안내 기능은 제외하고, **무슨 기능을 구현했는지**와 **어떤 방식으로 구현했는지**를 중심으로 정리하였다.

---

## 2. 프로젝트 개요

Alley Pass는 좁은 골목길이나 주차된 차량 사이를 통과할 때, 차량의 현재 상태와 주변 공간 여유를 바탕으로 운전자에게 주행 보조 정보를 제공하는 앱이다.  
현재 구현은 **Pleos Connect Emulator + AAOS + Pleos Vehicle SDK** 환경에서 진행했으며, 실제 차량 센서 대신 일부 요소는 가상 시뮬레이션으로 구성하였다.

핵심 흐름은 다음과 같다.

1. 차량 속도·기어·조향·브레이크 상태를 수신한다.
2. 수신한 값을 바탕으로 가상 차량의 위치와 방향을 계산한다.
3. 차체와 벽/주차 차량 사이의 간격을 계산한다.
4. 위험도를 판단하여 경고와 안내를 제공한다.
5. 특정 상황에서는 사용자 확인 후 Alley Pass 매크로를 가상 실행한다.

---

## 3. 구현 기능 요약

### 3.1 차량 상태 데이터 연동

#### 구현한 내용

- 차량 속도 수신
- 기어(P/R/N/D) 상태 수신
- 조향값 수신
- 브레이크 누름/해제 상태 수신
- 차량 정보 패널 표시

#### 어떻게 구현했는가

- **속도와 기어**는 AAOS(Android Automotive OS) 경로를 통해 수신하였다.
- **조향과 브레이크**는 Pleos Vehicle SDK를 통해 수신하였다.
- 수신한 값은 앱 내부 상태로 통합하고, 일정 시간 이상 값이 들어오지 않으면 미수신 상태로 처리하였다.
- 화면 오른쪽 정보 패널에 속도, 조향 방향/값, 브레이크 상태, 기어 상태를 표시하도록 구성하였다.

#### 구현 의미

차량의 실제 주행 상태를 받아와, 단순한 가상 앱이 아니라 **차량 상태 연동형 주행 보조 앱**의 형태를 갖추었다.

---

### 3.2 3D 골목길 주행 시뮬레이션

#### 구현한 내용

- 3D 골목길 환경 구성
- 내 차량의 전진/후진 이동 표현
- 조향에 따른 회전 이동 표현
- 주차 차량과 도로 경계 배치
- 가상 접촉 시 정지 처리

#### 어떻게 구현했는가

- Android 앱 내부에서 OpenGL ES 기반 3D 렌더링을 사용하였다.
- 가상 골목, 주차 차량, 내 차량을 단순화된 모델로 배치하였다.
- 속도와 조향 입력값을 이용해 차량의 위치와 방향을 매 프레임 갱신하였다.
- 벽이나 주차 차량과 접촉한 경우, 충돌 상태를 표시하고 가상 이동을 멈추도록 구성하였다.

#### 구현 의미

실제 수신한 차량 상태를 사용해 **운전 상황을 시각적으로 이해할 수 있는 3D 보조 화면**을 구현하였다.

---

### 3.3 차량 이동 계산

#### 구현한 내용

- 속도와 조향에 따라 차량이 이동하는 로직 구현
- 전진/후진 모두 반영
- 회전 반경을 반영한 곡선 이동 구현

#### 어떻게 구현했는가

- 차량 이동은 **자전거 운동 모델(Bicycle Model)** 을 단순화하여 적용하였다.
- 입력값은 다음과 같이 활용하였다.
  - 속도 `v`: AAOS에서 수신한 실제 차량 속도
  - 조향 `a`: Pleos SDK에서 수신한 조향값
- 조향값은 정규화한 뒤 최대 조향각으로 변환하여 사용하였다.
- 매 프레임에서 차량의 방향(heading)을 먼저 갱신하고, 그 방향으로 위치를 이동시켰다.
- 속도와 프레임 시간을 고려해 이동 구간을 여러 번 나누어 계산함으로써 장애물을 건너뛰는 현상을 줄였다.

#### 구현 의미

단순히 속도를 숫자로 보여주는 수준이 아니라, **실제 주행과 유사한 형태의 가상 이동**을 표현할 수 있게 되었다.

---

### 3.4 주변 거리 계산

#### 구현한 내용

- 차체와 벽 사이 간격 계산
- 차체와 주차 차량 사이 간격 계산
- 좌/우/앞/뒤 방향별 최소 거리 계산
- 차체 회전 상태를 반영한 거리 계산

#### 어떻게 구현했는가

- 차량을 중심 기준의 직사각형 차체로 단순화하였다.
- 조향에 따라 차량이 회전하면, 차체 네 모서리 좌표도 함께 갱신하도록 하였다.
- 벽, 주차 차량, 차체 모두를 기하학적 도형으로 보고 최소 거리를 계산하였다.
- 충돌 여부 판단에는 **분리축 정리(SAT)** 를 사용하였다.
- 충돌하지 않은 경우에는 **선분 간 최소 거리 계산**을 이용해 실제 여유 공간을 구했다.
- 단순히 중심점 사이의 거리가 아니라, **차체 외곽끼리의 최소 거리**를 기준으로 계산하였다.

#### 구현 의미

운전자 입장에서 중요한 것은 차량 중심이 아니라 실제 차체 외곽과 장애물 간 여유이기 때문에, **실제 체감과 더 가까운 거리 판단**이 가능하도록 구현하였다.

---

### 3.5 위험 감지 및 경고 안내

#### 구현한 내용

- 접촉 경고
- 초근접 경고
- 접근 중 경고
- 과속 안내
- 일반 주행 안내

#### 어떻게 구현했는가

- 계산된 최소 거리와 현재 속도를 기준으로 여러 단계의 경고 규칙을 만들었다.
- 예를 들어,
  - 접촉 시: 즉시 빨간 경고 표시 및 이동 정지
  - 거리 0.3m 이하: 정차 후 확인 안내
  - 거리 0.8m 이하: 공간 주의 안내
  - 거리 1.2m 이하이면서 점점 가까워지는 중: 접근 경고
  - 속도 10km/h 초과: 속도 감소 안내
- 이전 프레임의 거리와 현재 거리를 비교하여, 장애물에 가까워지고 있는지도 판단하였다.

#### 구현 의미

단순 정보 표시를 넘어서, 현재 상황을 앱이 해석하여 **운전자에게 판단 보조 메시지**를 제공하도록 하였다.

---

### 3.6 주행 방향 후보 비교

#### 구현한 내용

- 좌측, 직진, 우측 방향의 여유 공간 비교
- 더 안전한 방향 안내
- 교행 공간 부족 시 정차 권고

#### 어떻게 구현했는가

- 현재 속도를 기준으로 가상의 조향 후보 3개(좌/직진/우)를 설정하였다.
- 각 후보에 대해 약 2.5초 동안 진행했을 때의 최소 여유 공간을 계산하였다.
- 이 값을 비교해 직진보다 좌/우가 더 여유로운지 판단하고, 방향 안내 문구에 반영하였다.
- 모든 후보가 충분히 좁다면 정차 및 공간 확인을 우선 안내하도록 하였다.

#### 구현 의미

운전자가 막연히 “좁다”라고 느끼는 것이 아니라, **어느 방향이 상대적으로 여유가 있는지**를 참고할 수 있게 하였다.

---

### 3.7 Alley Pass 매크로 기능

#### 구현한 내용

- 반복 브레이크 감지
- 저속·근접 상황 판단
- 정차·P단 확인
- 사용자 확인 후 Alley Pass 매크로 실행

#### 어떻게 구현했는가

- 좁은 공간에서 운전자가 긴장하며 여러 번 브레이크를 밟는 상황을 Alley Pass 발동 조건으로 가정하였다.
- 조건은 다음과 같이 구성하였다.
  - 0~10km/h 저속 상태
  - 주변 거리 1.2m 이하
  - 15초 이내 브레이크 해제→누름 3회 감지
- 조건이 만족되면 감지 상태를 만들고, 이후 실제로 정차했는지와 P단 여부를 다시 확인하였다.
- 사용자 확인을 거친 뒤, 매크로를 순차적으로 실행하도록 구성하였다.

#### 구현 의미

위험하거나 불편한 상황을 앱이 감지하고, 사용자의 동의를 받아 **보조 기능을 단계적으로 실행하는 흐름**을 구현하였다.

---

### 3.8 매크로 시나리오의 가상 실행

#### 구현한 내용

- 미러 접기
- 조수석 창문 동작
- 비상등 3회 점멸
- 완료 단계 표시

#### 어떻게 구현했는가

- 현재 공개 SDK에서 일부 제어 기능은 확인되지 않았거나 실제 반영이 불확실했기 때문에, Alley Pass 매크로는 **가상 실행 방식**으로 구현하였다.
- 즉, 화면 상에서 단계별 카드와 상태 변화를 보여주며, “미러 → 창문 → 비상등 → 완료” 순서로 동작하도록 만들었다.
- 이 과정은 실제 차량 액추에이터를 제어하는 것이 아니라, 사용자가 기능 흐름을 이해하고 시연할 수 있도록 구성한 것이다.

#### 구현 의미

실제 제어가 완전히 검증되지 않은 상태에서도, **기획한 사용자 경험(UX) 흐름을 시연 가능한 형태로 구현**하였다.

---

### 3.9 Pleos Virtual Console 연동

#### 구현한 내용

- 앱에서 Virtual Console과 연결
- D/R/N/P 기어 조작
- 방향키 기반 가속/감속/조향 입력
- 재조회 및 연결 정리 처리

#### 어떻게 구현했는가

- Pleos Virtual Console의 내부 인터페이스와 연결하여 속도, 기어, 조향 관련 조작을 시도할 수 있도록 구성하였다.
- 앱 또는 입력 이벤트를 통해 기어를 바꾸고, 방향키 입력으로 가속/조향을 반영하였다.
- 상태 변화는 Console과 SDK 값을 다시 읽어 앱에 반영하였다.
- 연결 오류, 화면 이탈, 포커스 상실 상황에서는 입력을 정리하고 정차 상태로 복귀하도록 처리하였다.

#### 구현 의미

단순한 정적 화면이 아니라, **에뮬레이터와 상호작용하며 실험 가능한 구조**로 개발되었다.

---

### 3.10 일부 차량 제어 기능 검증

#### 구현한 내용

- 사이드미러 열선 제어 시험
- 앰비언트 스위치 제어 시험
- 창문, 도어, 조명 관련 쓰기 요청 시험

#### 어떻게 구현했는가

- Pleos Vehicle SDK에서 제공하는 제어 API를 확인하고, 디버그 환경에서 명시적 테스트를 수행하였다.
- 명령 요청 후 재조회하여 실제 값이 바뀌는지 확인하는 방식으로 검증하였다.
- 일부 기능은 변경 및 복원이 재조회로 확인되었고, 일부 기능은 요청은 성공했으나 실제 반영은 확인되지 않았다.

#### 구현 의미

향후 실제 매크로나 차량 제어 기능 확장 가능성을 확인하기 위한 **사전 검증 작업**을 수행하였다.

---

## 4. 전체 기능 흐름 요약

현재 구현된 Alley Pass의 전체 흐름은 다음과 같이 정리할 수 있다.

1. **차량 상태 수신**  
   속도, 기어, 조향, 브레이크 정보를 받아온다.

2. **가상 주행 계산**  
   수신한 값을 바탕으로 3D 공간에서 차량 위치와 방향을 계산한다.

3. **주변 여유 공간 계산**  
   차체와 벽/주차 차량 사이의 최소 거리를 구한다.

4. **위험도 판단 및 안내**  
   근접, 접촉, 접근, 과속 여부를 판단하여 경고를 표시한다.

5. **추가 보조 기능 실행**  
   특정 조건에서 Alley Pass 매크로를 가상 실행한다.

---

## 5. 현재 구현의 의의

이 프로젝트는 단순히 차량 정보를 보여주는 수준을 넘어서,

- **실제 차량 데이터 연동**
- **3D 공간 기반 거리 계산**
- **위험 상황 판단**
- **사용자 확인형 보조 기능 실행**

까지 연결한 점에 의미가 있다.

즉, Alley Pass는 현재 단계에서 **“차량 상태를 받아 좁은 골목길 상황을 가상 분석하고, 운전자에게 시각적으로 보조 정보를 제공하는 주행 지원 프로토타입”** 으로 정리할 수 있다.

---

## 6. 한계 및 구분해서 써야 할 점

기획서나 발표 자료에는 아래 내용을 명확히 구분해 쓰는 것이 좋다.

### 현재 구현 완료

- 차량 상태 연동
- 3D 차량 이동 시뮬레이션
- 벽/주차 차량과의 거리 계산
- 위험 경고 및 안내
- 방향별 공간 비교
- Alley Pass 매크로의 가상 실행 흐름

### 아직 추가 검증이 필요한 부분

- 실제 차량 센서 기반 거리 측정
- 실제 창문/미러/비상등 제어의 완전 검증
- 실차 환경에서의 보정 및 검증

따라서 현재 결과는 **실차 완성품**이 아니라, **Pleos 환경 기반의 주행 보조 프로토타입**으로 표현하는 것이 적절하다.
