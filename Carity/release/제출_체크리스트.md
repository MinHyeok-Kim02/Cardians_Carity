## 1. 제출용 APK가 개발용과 다른 점

제출용 APK에는 시뮬레이션과 튜토리얼이 들어갑니다(`android/app`). 라벨 뷰어는 PC 서버가 있어야 동작하는 개발 도구라서 제출하지 않습니다.

| 항목 | 개발용 (debug) | 제출용 (release) | 근거 |
|---|---|---|---|
| 패키지 이름 | `com.example.pleostest` | `com.carity.app` (`.env`의 `RELEASE_APP_ID`) | 제출 후에는 바꿀 수 없음 |
| 서명 | 디버그 키 | `release\carity-release.jks` | 출시용 서명 |
| 버전 | 2.0.0 (코드 2) | 2.0.0 (코드 2) | 버전 이름은 필수 입력 |
| 디버그 가능 | 예 | 아니오 | — |
| AI 문장 다듬기 | Qwen(PC) 또는 Claude | **사용 안 함**. 규칙 엔진 문장을 바로 읽음. API 키가 들어가지 않음 | 심사 중 외부 서버를 켜 둘 수 없음 |
| PC 라벨 불러오기, PC 음성 | 사용 | **숨김 / 사용 안 함**. 앱 내장 라벨 장면 6개 사용 | 같은 이유 |
| 위치 권한 (`FUSED_LOCATION`) | 진단용으로 사용 | **선언 안 함** | 권한 최소화, 위치 약관 URL 불필요 |
| 창문·미러·조명 제어 권한 | 에뮬레이터 시험용 | **선언 안 함** | 승인 안 된 Vehicle SDK 권한이 있으면 심사 불가 |
| Console 키보드·가상 키보드·기어 요청·실제 조명 연동 버튼 | 보임 | **숨김** | 개발·시험 기능 제외 |
| 3D 자동 시연 | 에뮬레이터 | **정차 중 허용** (가상 주행, 실제 차량 값 변경 없음) | 핵심 기능 시연 |
| 주행 중 화면 (`distractionOptimized`) | 선언함 | **선언 안 함** → 주행 중에는 Pleos가 앱 화면을 제한 | 운전자 주의 분산 기준 |

4단계에서 확인할 것:

- [ ] 실행 직후 강제 종료가 없고 10초 안에 화면이 뜬다
- [ ] `[라벨 장애물·AI 판단]` 탭 → 장면 선택 → 판단 문장이 나오고 음성으로 읽어 준다 (Pleos TTS)
- [ ] 3D 자동 시연이 끝까지 달린다
- [ ] "튜토리얼로 보기"와 Carity 튜토리얼 6단계가 끝까지 진행된다
- [ ] 개발용 버튼(Console 키보드, 가상 키보드, 기어 D/R/N/P, 무드라이트 연동, PC 라벨 불러오기, AI 다시 판단)이 보이지 않는다

빌드가 실패하면 창에 나온 오류를 그대로 알려 주세요.

### 3-1. 자세한 설명 (한국어 초안)

Carity는 좁은 골목, 양쪽에 차가 주차된 길, 마주 오는 차가 있는 좁은 길에서 초보 운전자가 어떻게 지나가야 할지 미리 연습하고 안내받는 앱입니다.

실제 블랙박스 영상에서 얻은 장면을 3D 골목으로 다시 만들고, 차체와 장애물 사이에 남은 간격과 지나갈 경로를 계산해 행동을 안내합니다.

- 3D 골목 시뮬레이션: 왼쪽·오른쪽 간격을 계산해 0.8미터 이하 주의, 0.3미터 이하 경고로 알려 줍니다.
- 실제 주행 장면 판단: 블랙박스 장면 6개에서 지나갈 수 있는지, 양보해야 하는지, 멈춰야 하는지 판단합니다.
- 튜토리얼: 상황 설명 → 판단 → 노면 화살표 → 먼저 지나가는 차 미리 보기 → 따라 주행 순서로 연습합니다.
- 음성 안내: "왼쪽에 가깝습니다. 40센티미터입니다. 핸들을 오른쪽으로 살짝 돌리세요."처럼 짧게 알려 줍니다.

시뮬레이션과 튜토리얼은 정차 중에 사용하며, 주행 중에는 화면이 제한됩니다. 앱은 차량을 제어하지 않습니다. 화면의 거리는 가상 장면 기준 값이며 실제 센서 측정값이 아닙니다.

### 3-2. 심사 메모 · 기능 매뉴얼 (초안)

- 로그인이나 계정이 필요 없습니다. 모든 기능이 설치 직후 바로 열립니다.
- 외부 서버를 쓰지 않습니다. 판단과 음성은 모두 기기 안에서 처리합니다(Pleos TTS 기기 내 합성).
- 확인 방법 (정차, P단 상태):
  1. Carity 시뮬레이션 실행 → 오른쪽 `[라벨 장애물·AI 판단]` 탭 → `장면 선택` → 장면 하나 선택 → 판단 문장과 음성 확인
  2. 하단 `3D 자동 시연` → 차가 경로를 따라 끝까지 주행하며 간격 경고와 음성 안내
  3. `튜토리얼로 보기` 또는 Carity 튜토리얼 실행 → 6단계 자동 진행
- 실내 조명 그림과 Alley Pass 매크로(미러·창문·비상등)는 화면 연출이며 실제 차량을 제어하지 않습니다.

## 4. 결정이 필요하거나 남은 위험

| 항목 | 내용 |
|---|---|
| 패키지 이름 | `com.carity.app`로 정했습니다. 팀에서 다른 이름을 원하면 첫 빌드 전에 `.env`의 `RELEASE_APP_ID`를 바꾸세요. 제출 후에는 바꿀 수 없습니다. |
| Vehicle SDK 권한 승인 | 심사 가이드상 Vehicle SDK 권한은 Pleos App Market과 **사전 협의·승인된 것만** 선언할 수 있습니다. `CAR_DRIVE`(조향·브레이크) 승인 여부를 콘솔에서 확인하세요. 승인이 안 되면 이 권한을 빼고 차속만 쓰는 방향으로 바꿔야 합니다. |
| 주행 중 사용 | 제출용은 주행 중 화면 제한을 따르므로 주행 중에는 앱 화면이 가려집니다. 주행 중 안내까지 하려면 운전자 주의 분산 기준에 맞춘 별도 주행 화면이 필요합니다. |
| 시험용 코드 | 예전 시험 코드(`com.example.myapplication`, 차량 제어 시험 클래스)가 APK 안에 남아 있습니다. 화면에서는 실행되지 않지만, "시험용 파일 없음" 기준을 엄격히 적용하면 지적될 수 있습니다. 필요하면 정리하겠습니다. |
| 빌드 검증 | 제 환경에서는 Gradle을 실행할 수 없어 아직 빌드해 보지 못했습니다. 2장 순서로 빌드한 뒤 결과를 알려 주세요. |
